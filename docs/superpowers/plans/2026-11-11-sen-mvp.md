# Sen MVP v1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the complete, Scope-Frozen `Sen MVP v1.0` Go CLI (`sen`), 5-table SQLite WAL ledger, Companion Skills bridge (`superpowers`, `security-audit`, `vn-law-check`), Antigravity 4-event hook adapter, SmartScreen-safe installer, and 6-scenario Adversarial Anti-Cheat E2E test suite.

**Architecture:** A zero-CGO Go `1.22+` binary (`cmd/sen`) backed by `modernc.org/sqlite` (WAL mode, 5 tables: `rules`, `requirements`, `tasks`, `snapshots`, `evidence`) with zero LLM API dependencies. `sen` acts as a deterministic ledger and verification referee across any IDE via a 35-line `AGENTS.md` (with Progressive Companion Skill routing) and upgrades to pre-execution prevention on Antigravity via `.agents/hooks.json`.

**Tech Stack:** Go `1.22+`, `modernc.org/sqlite`, Windows/POSIX `os/exec` (`exec.CommandContext`), PowerShell 5.1+/7 installer (`SHA-256` verification + `Unblock-File`).

**Spec:** `d:/TUNBH/Workspace/Code/sen-mvp/docs/SPEC.md`

## Global Constraints

- Exact 8 top-level CLI commands: `init`, `brief`, `intake`, `begin`, `verify`, `undo`, `done`, `status`.
- Exact 5 SQLite tables: `rules`, `requirements`, `tasks`, `snapshots`, `evidence` (no extra tables).
- Hard cap of `<= 20` rows in `rules`; insert past 20 must fail deterministically unless `--replace` or `--delete` is used.
- Zero `sh -c` or `cmd /C` execution in `verify` or `done`; strip `*KEY*`, `*TOKEN*`, `*SECRET*`, `*PASSWORD*`, `*CREDENTIAL*` from child `Env`.
- Media/large files `> 10MB` (`10 * 1024 * 1024` bytes) must not be copied into `.sen/snapshots/` or hashed byte-by-byte during baseline scan; track `orig_size + orig_mtime_ns` only.
- Every source file must stay well under `800` lines and `45 KB` (clean modular SRP).

## Review Focus

- Empty test suites returning exit code `0` (`go test` printing `[no test files]`, `pytest` exit `5`, `jest --passWithNoTests` with `0 passed`) must be rejected by `sen verify` when strength is `TEST`.
- Pre-existing test files (`*_test.go`, `test_*.py`, `*.test.ts`, `*.spec.js`, etc.) locked at `sen begin` must cause `sen verify` to fail immediately if modified, even if included in `--files` (unless `--unlock-tests` is never exposed to the agent).
- Out-of-scope edits in non-Git folders (including newly created untracked files outside `scope_files` and outside `.sen/`) must be caught against `__BASELINE__` in both `sen verify` and `sen done`.
- Windows path separators (`\` vs `/`) and case-insensitive NTFS paths must normalize cleanly to forward-slash workspace-relative paths across `snapshots`, `scope_files`, and `path_glob`.
- Antigravity hook payloads (`camelCase` JSON on stdin: `hookEventName`, `lastUserInput`, `toolCall.name`, `toolCall.args`, `terminationReason`) must never crash or block read-only tools when `.sen/state.db` is not initialized yet.
